# 系统说明

## 系统用途

AI-auto-lrc 接收已有歌词和对应歌曲音频，为歌词计算时间戳，输出可供播放器使用的 LRC。用户需要准备同一录音版本的正确歌词；系统不从音频自动识别或创作歌词，不提供网页、HTTP 服务或常驻任务调度。

当前为 `2.0.0a0` Alpha。本地核心流程已有实测，完整异常场景和发布资格暂未覆盖，详见[项目状态](PROJECT_STATUS.zh-CN.md)。

## 输入与输出

| 项目 | 行为 |
|---|---|
| 歌词 | 推荐 UTF-8 纯文本，一行一句；CLI 支持 BOM 和受控编码回退；API 接收字符串 tuple |
| 音频 | 本地文件；真实 WAV/MP3 有已有测试，其他格式取决于所用解码器能力 |
| 默认处理 | MTL、torchaudio、严格完整性、不分离人声；设备 auto 在 CUDA 可用时选择 CUDA，否则 CPU |
| 默认输出 | 行级 `[mm:ss.mmm]歌词`；显式 word 模式在行中增加 `<mm:ss.mmm>` token 时间戳 |
| CLI 文件 | `-o` 指定输出；父目录自动创建，现有普通文件原子替换 |
| CLI 标准输出 | 不指定 `-o` 时只输出 LRC，含一个尾换行；进度与诊断进入 stderr |
| API | 返回结构化结果，由调用方决定如何显示、保存和处理 |

中文、英文、日文、韩文和俄文存在音素处理路径，但不能据此推断每种语言和混合语言的对齐准确率已合格。逐词时间戳对应内部 token，未必等同所有语言的自然语言“词”。

## 处理流程

```text
歌词文件 -> 编码读取 -> 清理/语言识别/音素准备 ─┐
                                                ├-> 模型推理 -> DTW/可选 BDR
音频文件 -> torchaudio -> 首声道/重采样/Mel ────┘
  -> 检查对齐完整性 -> 渲染 LRC -> 结构化结果 -> CLI stdout 或原子输出文件
```

Python API 与 CLI 共享应用用例。模型适配层保留 LegacyV1 数值行为，应用层负责组织流程和严格/partial 策略。依赖与模型资产要在运行前准备完成；核心默认路径不下载模型。

## 运行条件和资产

Python 支持范围为 `>=3.10,<3.12`，建议先使用 Python 3.11 与 CPU。macOS arm64 / Python 3.11.4 有本地记录；MPS 不是可选设备。Linux x86_64 的锁定依赖默认指向 PyTorch CPU wheel，因此不要从 `--device cuda` 选项存在推断默认安装已经支持 GPU。

使用 `pyproject.toml + uv.lock` 安装，模型文件通过 Git LFS 准备；NLTK 数据也必须就绪。安装依赖和拉取 LFS 可需要网络，“离线”描述的是资产齐备后的核心处理路径。资产清单、完整安装命令见[使用指南](USER_GUIDE.zh-CN.md)。

## 运行边界

- `--allow-partial` 必须显式选择，只接受非空连续前缀，退出码为 3。默认失败不会自动变成部分成功。
- 输出不能与输入相同或互为别名；拒绝符号链接祖先和非普通文件。macOS 临时目录应使用 `/private/var/...` 等规范真实路径。
- API 不负责写 LRC，也不主动打印进度；运行时仍会读取输入、准备私有资产副本，第三方库可能产生警告。
- runtime 可复用，同一 runtime 内模型加载/推理串行。尚无公共 `close()` 或上下文管理协议，长驻服务的完整回收与并发容量尚未验收。
- `max_alignment_bytes` 仅约束 DTW 分配估算，不能作为整个进程的 RAM 上限；长歌曲仍需容量评估。
- 可选 Demucs 是实验路径，可能下载权重，当前 `offline=True` 未在该分离器中完整执行离线约束，不能用作隔离网络承诺。

训练、旧评估脚本、v1 扩展转换工具不属于 v2 发布接口。需要集成时阅读[技术指南](TECHNICAL_GUIDE.zh-CN.md)；旧代码按[迁移指南](V1_TO_V2_MIGRATION.zh-CN.md)改造。
